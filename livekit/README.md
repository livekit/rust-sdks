# LiveKit Client SDK

The official client SDK for [LiveKit](https://livekit.com).

Use this SDK to add realtime video, audio and data features to your Rust app.

## FlexFEC

Published video can be protected with proactive FlexFEC-03 forward error
correction, letting receivers (the LiveKit SFU or peers) repair packet loss
without waiting for retransmissions:

```rust
use livekit::options::{FlexFecOptions, FlexFecProtection, TrackPublishOptions};

let mut options = RoomOptions::default();
options.flexfec = Some(FlexFecOptions::new(FlexFecProtection::Medium));
let (room, events) = Room::connect(&url, &token, options).await?;

// Each protected video track opts in when it is published. The room-level
// options above supply the shared protection level.
room.local_participant()
    .publish_track(
        LocalTrack::Video(track),
        TrackPublishOptions {
            flexfec: true,
            simulcast: false,
            ..Default::default()
        },
    )
    .await?;
```

Notes:

- The configuration is process wide and must be supplied on the first room
  the process connects (the WebRTC field trials are bound to the peer
  connection factory). `Room::set_flexfec_options` adjusts the protection
  parameters at runtime, `Room::fec_sender_stats` reports the FEC send rate.
- Each video track that should be protected must set
  `TrackPublishOptions::flexfec` when it is published. Tracks that leave it
  disabled do not negotiate a FlexFEC repair stream. If a track requests
  FlexFEC without room-level configuration, publication continues without FEC
  and logs a warning.
- FlexFEC protects the first simulcast layer only, publishing with
  `simulcast: false` is recommended for protected tracks.
- Receiving FlexFEC repair streams (e.g. generated by the SFU) requires no
  configuration.
- FEC spends bandwidth proactively: it pays off on links where loss is
  bursty or the RTT makes retransmissions slow, and costs throughput on
  clean or low-latency links.
